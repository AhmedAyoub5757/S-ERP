# Greenwood School ERP (S‑ERP)

**Live demo:** https://s-erp-alpha.vercel.app

---

## 📖 Overview
A modern, role‑based School Management System built with **Next.js 16** and **Supabase**. Supports administrators, teachers, students, and parents with secure row‑level security. The app is deployed on Vercel and follows production‑readiness best practices.

---

## 📂 Project Structure (relevant parts)
```
app/
├─ layout.tsx            # Global metadata, icons, Open Graph, Twitter cards
├─ page.tsx              # Root redirects to /dashboard (protected)
├─ login/
│   ├─ page.tsx          # Login UI + page‑level metadata (noindex)
│   └─ actions.ts        # Supabase auth actions (unchanged)
├─ dashboard/            # Private routes – **not** indexed
│   ├─ page.tsx          # Dashboard landing
│   └─ …                 # Various feature pages (students, teachers, …)
├─ sitemap.ts            # Dynamic sitemap (public routes only)
└─ robots.ts             # robots.txt – disallow /dashboard & /api
public/
├─ favicon-48x48.png
├─ favicon-32x32.png
├─ favicon-16x16.png
├─ apple-touch-icon.png
└─ s_erp_master_icon.png   # 512×512 PNG for OG/Twitter
scripts/
└─ generate_icons.ps1    # Generates the PNG favicons from the master JPG
```

## 🛠️ Production‑Readiness Additions
### 1. Metadata & Branding (app/layout.tsx)
- Title, description, Open Graph, Twitter cards.
- Icon links point to generated favicons.
- Uses the master PNG (`/s_erp_master_icon.png`).

### 2. Login Page Metadata (app/login/page.tsx)
- `title`, `description`, `robots: { index:false, follow:false }`.
- OG/Twitter images reference the master PNG.

### 3. SEO Assets
- **Favicons** (16/32/48) and **Apple touch icon** generated from the master JPG via `scripts/generate_icons.ps1`.
- **Sitemap** (`/sitemap.xml`) – only public routes (`/`, `/login`).
- **robots.txt** – allows crawling of public pages, disallows `/dashboard` and `/api`.

### 4. Load‑Testing & Auditing Documentation (`docs/production-readiness.md`)
- Conservative Autocannon command and interpretation guide.
- Vercel fair‑use warnings.
- Lighthouse CLI commands for desktop & mobile.
- Step‑by‑step local production build verification.

## 📋 How to Run Locally (Production Mode)
```bash
# 1️⃣ Build the app
npm run build
# Ensure the build succeeds; fix any errors before proceeding.

# 2️⃣ Start the production server
npm start
# The app will be available at http://localhost:3000
```
Visit `/login` to see the public page and `/dashboard` (requires authentication) to verify protection.

---

## 📊 Performance Auditing
```bash
# Desktop report
npx lighthouse https://s-erp-alpha.vercel.app/login --view

# Mobile preset
npx lighthouse https://s-erp-alpha.vercel.app/login --preset=mobile --view
```
Results are saved locally and opened in the browser.

---

## 🚧 Load‑Testing (Manual)
```bash
# Conservative public‑only test (run manually when needed)
npx autocannon -c 5 -d 15 -p 1 https://s-erp-alpha.vercel.app/login
```
Do **not** stress test authenticated routes without a valid session cookie.
