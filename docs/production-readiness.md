# Production‑Readiness Guide

## 1. Load‑Testing with Autocannon
```
# Conservative public‑only test (run manually when needed)
npx autocannon -c 5 -d 15 -p 1 https://s-erp-alpha.vercel.app/login
```
- **`-c 5`** – 5 concurrent connections.
- **`-d 15`** – 15‑second duration.
- **`-p 1`** – 1 pipelined request per connection.

### What the output means
| Metric | Meaning |
|--------|---------|
| **Requests/sec** | Throughput – how many HTTP requests were completed per second. |
| **Latency** | Time between request sent and response received. Shows *average* and percentile values (p50, p90, p99). |
| **2xx** | Successful responses. |
| **4xx** | Client‑side errors (e.g., bad request, unauthorized). |
| **5xx** | Server‑side errors. |
| **Timeouts / connection failures** | Network‑level problems.

### Why we avoid authenticated routes
- Without a valid session cookie the request hits a redirect or a 401/403, which does not reflect the real performance of the dashboard.
- Even with a cookie, session expiration and data‑dependent logic can make results noisy.
- Load‑testing private APIs could unintentionally stress the database or expose sensitive data.

## 2. Vercel Fair‑Use Caution
Running load‑tests against a production Vercel deployment consumes serverless function invocations and bandwidth. Excessive load may trigger:
- Rate‑limits on function execution.
- Automatic throttling or temporary bans.
- Unexpected billing spikes.

**Keep tests conservative** (as shown above) and run them only when you have a specific reason.

## 3. Lighthouse Performance Auditing
### Desktop audit
```
npx lighthouse https://s-erp-alpha.vercel.app/login --view
```
### Mobile audit (preset)
```
npx lighthouse https://s-erp-alpha.vercel.app/login --preset=mobile --view
```
The `--view` flag opens the generated report in the default browser.

## 4. Production Build Verification (local)
1. **Build**
   ```bash
   npm run build
   ```
   - The command must finish without errors. If it fails, fix the reported issues before proceeding.
2. **Start**
   ```bash
   npm start
   ```
   - The app runs in production mode on `http://localhost:3000`. Verify that pages render correctly, metadata appears, and protected routes still enforce authentication.
